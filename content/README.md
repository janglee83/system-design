# Content

Learning content for System Design Lab: a curriculum from level 0 (never heard of a load balancer)
to level 100 (can design, defend and debug large distributed systems). Everything here is written by
us. Other books, courses and products — including the reference product — are used only as a map of
topics; their text, exercises, scenarios, hints and diagrams are never copied or lightly reworded.

## Layout

```
content/
├─ README.md                         this file
├─ levels.json                       levels, lesson/challenge order, roadmap stubs, engine catalogs and gaps
├─ curriculum.json                   GENERATED by `sim-cli content curriculum content`; never hand-edit
├─ lessons/<lesson-id>/lesson.json   structured part: metadata and an experiment or a check
├─ lessons/<lesson-id>/vi.md         Vietnamese prose
├─ lessons/<lesson-id>/en.md         English prose
├─ challenges/<challenge-id>/…       challenge.json, vi.md, en.md
├─ research/<topic>.md               research notes with citations (facts in our words)
├─ drafts/<lesson>.md                old single-file drafts, removed once all are migrated
└─ REPORT.md                         the latest content-researcher run report
```

The format is defined in `docs/superpowers/specs/2026-10-20-content-format-design.md`, with
rulings in `docs/superpowers/plans/2026-10-20-content-format.md`. Working examples:
`crates/content/tests/fixtures/good/`.

### Checking your work

- `pnpm content:validate`: every lesson and challenge, run on the real engine. `FAIL` lines
  must be fixed in the content; `WARN … content.blocked` lists engine features an item is
  waiting for. Add `--json` (`cargo run -q -p sim-cli -- content validate content --json`)
  to see the measured metrics of every run under `runs`.
- `pnpm content:curriculum`: regenerate `curriculum.json` after any change; CI fails when it
  is stale.

### levels.json

- `levels[]`: L0 to L6 with score range, entry assumptions, outcomes, an `exitCheck`, and
  the ordered `lessons` and `challenges` ids. A prerequisite must come earlier in this order.
- `roadmap`: planning stubs for items without a folder. Remove the stub when you add the folder.
- `engine.planned`: engine features a plan covers but the engine lacks; items using them are
  reported as blocked, not failing. A name that is neither built nor planned is an error.
- `engineGaps`: engine features no plan covers yet, each with `neededBy` item ids.

### `research/<topic>.md`

One note per topic, shared by the lessons that use it. Sections: key facts (numbered, each with
citation markers), numbers worth remembering, how the topic maps to the engine (including checked
numbers and gaps), misconceptions, analogy ideas, caveats, sources. Sources list title,
author/organisation, URL and date (or "accessed" date). One-sentence quotations are allowed only
here, with a citation.

## Authoring checklist (every lesson)

1. **Outcome** — one observable sentence ("choose …", "show …", "compute …").
2. **Prerequisites** — lesson ids that come earlier in `levels.json` order.
3. **Analogy first**, then the precise term. Every new term is defined at first use. In Vietnamese,
   technical terms stay in English with a Vietnamese explanation the first time
   (e.g. "**cache** (bộ nhớ đệm)").
4. **Misconceptions** — 2–4 that beginners actually hold, labelled M1…; say which ones have no
   experiment choice.
5. **Experiment** — in `lesson.json`: controls, one correct choice, one wrong choice per
   misconception with the goals it fails (`failsGoals`), and numeric `expect` ranges measured with
   `content validate --json` (never guessed). Anything the engine lacks goes in `levels.json`
   (`engine.planned` or `engineGaps`). Prefer goals on `p95`/`p99`,
   `requestsRejected`, `spofCount`, `costPerMonth`; note that in 1a an overloaded node can still show
   availability above 0.99.
6. **Feedback** for each wrong choice, in plain words, explaining the mechanism (not just "wrong").
7. **Takeaways** — 2–4 short lines.
8. **Review questions** with short answers, for spaced repetition.
9. **Bilingual** — VI and EN written separately; same facts, numbers and choices in both.
10. **Sources** — every claim traceable to the research note's source list.

Before marking a draft ready:

- [ ] Numbers in both languages match the experiment spec.
- [ ] `pnpm content:validate` passes: the correct choice meets every goal and each wrong choice
      fails the goals it lists.
- [ ] No sentence, exercise, scenario or hint resembles a source's wording (re-read the notes'
      sources side by side if unsure).
- [ ] Game-world numbers (vCPU capacity, prices) are presented as lab assumptions, not real
      benchmarks.
- [ ] No English left inside Vietnamese prose except technical terms (and vice versa).
- [ ] `pnpm content:curriculum` was run and the regenerated `curriculum.json` is committed.
