# App Shell and Lab Canvas Implementation Plan (sub-project 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The first usable product. A Next.js app (`apps/web`) where a learner builds a system on a canvas, runs it on our wasm engine in a Web Worker, and watches it play back, plus the app shell (navigation, command palette, language, theme, help) that sub-projects 4–6 plug into.

**Architecture:** Next.js 15 App Router under `/[locale]/…` (`vi`, `en`) with `next-intl`. The Lab is one client component tree. Its state lives in three Zustand stores: `design` (graph, layout, groups, workload, faults, world parameters, with undo/redo), `run` (the last 10 results), and `playback` (the clock). A dedicated Web Worker owns the wasm instance from `@sd/sim/web` and answers typed messages (`validate`, `run`, `trace`, `listComponents`, `defaultCalibration`, `capabilities`, …). React Flow 12 renders the canvas. A single `<canvas>` layer above it draws the request dots. Designs, presets and the autosaved draft live in IndexedDB. Content (curriculum, challenges) is read from `content/` by server components at build or request time and handed to the client as plain props.

**Tech Stack:** Docker dev container (`./dev <cmd>`, Rust 1.85.1, Node 24, pnpm 10, Playwright Chromium baked into the image); Next.js 15.5.27, React 19.3.0, TypeScript 5.9.3, `@xyflow/react` 12.12.0, `elkjs` 0.12.0, Zustand 5.0.15, Tailwind CSS 4.3.3, Radix UI primitives, `lucide-react` 1.52.0, `next-intl` 4.14.9, `uplot` 1.6.32, `idb` 8.0.3, `cmdk` 1.1.1, `fuse.js` 7.5.0, `zod` 4.6.5; Vitest 5.0.3 + Testing Library + jsdom; Playwright 1.63.0 + `@axe-core/playwright` 4.13.0.

## Rulings on spec ambiguities

The spec leaves these points open. Each ruling below is what this plan implements. The owner can overturn any of them before Phase 1 starts.

| # | Topic | Ruling |
|---|---|---|
| R1 | Engine change | The only engine change is a `capabilities()` export in `crates/sim-wasm` (Task 1). It serializes `sim_core::capabilities()` through a local `CapabilitiesJs` struct, so `sim-core` gains no `Serialize` derive and does not change at all. `@sd/sim` gains `Sim.capabilities()` and a hand-written `Capabilities` TS type. |
| R2 | How the wasm is loaded and served | The worker imports `loadSim` from `@sd/sim/web` and calls it **without** a URL. The wasm-bindgen `web` glue then runs `new URL('sim_wasm_bg.wasm', import.meta.url)`. Webpack 5 (which Next uses) treats that expression as an asset reference: it copies the file to `.next/static/media/sim_wasm_bg.<hash>.wasm` and rewrites the URL to `/_next/static/media/sim_wasm_bg.<hash>.wasm`. Next serves that path with `Content-Type: application/wasm` and an immutable cache header, so `WebAssembly.instantiateStreaming` works and a new engine build gets a new URL. The worker is created with `new Worker(new URL("./sim.worker.ts", import.meta.url), { type: "module" })`, which webpack bundles as its own chunk. `next.config.ts` sets `transpilePackages: ["@sd/sim", "@sd/content"]` because both export TypeScript source. **Turbopack is not used** (`next dev` and `next build` without `--turbopack`), because this wiring is only verified for webpack. A Playwright smoke test (Task 7) proves all of it in Chromium: the worker reports the engine version, the `.wasm` response is 200 with `application/wasm`, and there are no console errors. **Fallback, only if that smoke test shows the asset is not emitted:** Task 7 Step 9 copies the file to `public/engine/sim_wasm_bg.<sha256-12>.wasm` in `ensure-wasm.mjs`, writes the URL to a generated (gitignored) `src/engine/wasm-url.ts`, and the worker passes it to `loadSim(url)`. |
| R3 | Building the wasm before the app | `packages/sim/wasm/` stays gitignored. `apps/web/scripts/ensure-wasm.mjs` runs before `dev`, `build` and `test`. It runs `pnpm --filter @sd/sim build:wasm` only when `packages/sim/wasm/web/sim_wasm_bg.wasm` or `packages/sim/wasm/node/sim_wasm_bg.wasm` is missing, or is older than the newest file under `crates/sim-core/src`, `crates/sim-wasm/src`, `crates/sim-*/Cargo.toml` and `Cargo.lock`. |
| R4 | Playwright in Docker | **Browsers are installed in the dev image**, not run from the official Playwright image. The dev image already has Rust, wasm-pack, Node and the workspace volumes. The e2e run needs the wasm build, `next build` and `next start` in the same container as the browser. A second image (Ubuntu-based) would need the build output and `node_modules` volumes shared across two images with different base OSes. Only Chromium is installed (`npx playwright@1.63.0 install --with-deps chromium`, browsers in `/ms-playwright`). The image tag goes from `system-design-dev:1` to `:2`, so `./dev` rebuilds stale local images. A unit test fails when the Dockerfile's Playwright version differs from `@playwright/test` in `apps/web/package.json`. Fonts come from npm packages (`@fontsource/*`), so screenshots do not depend on system fonts. |
| R5 | `web` compose service | `web` `extends` `dev`, runs `pnpm --filter @sd/web dev` (`next dev -H 0.0.0.0 -p 3000`), and publishes `3000:3000`. New named volumes: `node-modules-web` (`/work/apps/web/node_modules`) and `web-next` (`/work/apps/web/.next`; keeps the build cache off the macOS bind mount). `NEXT_TELEMETRY_DISABLED=1` is set in the image, because the app must not call external services. |
| R6 | Routing and locale | `next-intl` routing: locales `["vi", "en"]`, default `vi`, `localePrefix: "always"`, locale cookie `NEXT_LOCALE` kept for a year. The middleware picks the browser language on a first visit (`Accept-Language`) and the cookie afterwards. The language switch sets the cookie and replaces the route with the same path in the other locale. `/` and `/{locale}` redirect to `/{locale}/lab`. |
| R7 | Message keys | Catalogs are nested JSON. An engine code `a.b` is the nested key `a → b`. Top-level namespaces: `common`, `meta`, `nav`, `language`, `theme`, `help`, `shell`, `lab`, `palette`, `inspector`, `workload`, `faults`, `world`, `run`, `playback`, `trace`, `panel`, `designs`, `importIssue`, `tour`, `shortcuts`, `learn`, `challenges`, `leaderboard`, `component` (by kind, from `labelKey`), `componentDescription`, `category`, `role`, `edgeKind`, `configField`, `configOption`, `override`, `calibration`, `profile`, `arrivals`, `fault` (by kind), `metric`, `timelineField`, `traceOutcome`, `traceAction`, `engine.event`, `engine.validation`, `unit`. |
| R8 | Every engine code is translated | `src/i18n/engine-codes.ts` lists every event and validation code. A unit test reads `crates/sim-core/src/**/*.rs` (non-test code), extracts event codes (`event(…, "x.y", …)` and `code: "x.y"`) and the validation codes (the `pub mod codes` constants), and fails when the list and the engine differ. A second test fails when either catalog misses a key for any of: the event and validation codes; all 14 fault kinds; every `labelKey`, description, category, config field and choice option from `listComponents()`; every `capabilities().nodeOverrideKeys` and `workloadParams` entry; every `defaultCalibration()` field; every `Metrics` key; every profile, arrival mode, edge kind, timeline field, trace outcome and trace action. The two catalogs must have the same key set and the same ICU argument names per key. A Vietnamese value longer than 12 characters that equals the English value fails, unless its key is listed in `src/i18n/same-in-both.ts`. This catches English left inside Vietnamese text. |
| R9 | Hard-coded strings | ESLint `i18next/no-literal-string` (eslint-plugin-i18next 6.1.5), `mode: "jsx-only"`. It flags JSX text and the user-facing attributes `aria-label`, `aria-description`, `aria-roledescription`, `aria-valuetext`, `aria-placeholder`, `title`, `placeholder`, `alt`, `label` in `app/**/*.tsx` and `src/**/*.tsx`. Tests are excluded. A unit test lints a fixture through the ESLint API and proves the rule fires. Strings outside JSX (toast text, `document.title`) must go through `t()`. That is a review item, because the rule cannot see them. |
| R10 | Per-node monthly cost | The engine has no per-node cost API, and adding one would change `sim-core`. The worker computes it with the existing `simulate`: for each non-client node, a 100 ms run of `client → node` (edge kind = the node's first accepted kind, `baseRps: 0`) with the design's calibration. Its `costPerMonth` is the node's cost. A unit test checks that the per-node costs sum to the full design's `costPerMonth`. A node whose config the engine rejects shows "—". |
| R11 | Live validation | The worker's `validate` message runs `validateGraph(graph, limits)` (limits come from a challenge, else `null`) and computes the node costs. It is debounced 150 ms after each change. Workload and world-parameter inputs enforce their own bounds. Anything the engine still rejects at run time (`workload.invalid`, `calibration.invalid`) arrives as `SimValidationError` and is shown in the same problems list. Run is disabled while a blocking issue exists. |
| R12 | Design model | A design stores nodes with **absolute** positions, edges, groups, workload, faults, calibration overrides, duration, seed, locked node ids and an optional challenge reference (`designFormatVersion: 1`). New node ids are `<kind>-<n>` (`web-server-1`), edge ids `e<n>`, group ids `g<n>`; `n` is the lowest unused number. A new node's `label` is `""`, and the UI shows the translated component name plus `n`, so a label never freezes one language. **Locked** (from a challenge): cannot be deleted, renamed or reconfigured, and replicas cannot change. It can be moved, and its edges are free. This matches content ruling R15. |
| R13 | Connecting | A drag or the keyboard picker creates an edge whose kind is inferred: `db` when the target's role is `database`, otherwise `http` (spec §5.1). A target that accepts no edge kind (a client) refuses the connection and shows the translated `edge.not-accepted` message. Self-loops and duplicate `from→to` pairs are refused silently. A kind the target does not accept can still be chosen in the inspector, and validation then flags it. |
| R14 | Edges and layout | Orthogonal edges are React Flow `smoothstep` edges (`borderRadius: 8`). Auto-layout uses elkjs `layered`, direction `RIGHT`, `elk.edgeRouting: ORTHOGONAL`. Only node positions are taken from ELK; React Flow draws the edges. Nodes are 184 × 76 px for layout. Snap grid is 16 px. |
| R15 | Groups | A group is a React Flow node of type `group` (a labelled frame). Its members get `parentId` and a position relative to the group, converted from and to the absolute positions in the design. Dragging the frame moves the members. Grouping the selection makes a frame 32 px around the selected nodes' bounding box. Ungroup keeps the members' absolute positions. Groups never reach `SimInput`. |
| R16 | Undo/redo | The history keeps up to 200 design snapshots (spec: at least 100). A drag is one step, committed on drag stop. Selection, viewport and run results are not in the history. Undo/redo of a locked node is impossible because locked nodes cannot change. |
| R17 | Config fields | The engine's `FieldKind` is `number` or `choice` today. `number` renders a stepper (step 1 when `integer`, else 0.5) clamped to `min..max`. `choice` renders a select. A field whose `default` is a boolean renders a switch (none exist yet; covered by a unit test with a synthetic field). Labels come from `configField.<key>`, options from `configOption.<key>.<option>`. |
| R18 | Running | ⌘↵ / Ctrl+↵ or the Run button. The worker keeps the `SimRun` handles of the last 10 runs (for `trace(i)` and JSON export) and frees older ones. The main thread keeps the same 10 results as plain data (metrics, events, timeline header + transferred `Float32Array`, trace summaries, input, elapsed ms). A new run selects itself and resets playback to 0 s, paused. |
| R19 | Playback | 1× plays one simulated second per real second. Speeds are 0.25, 0.5, 1, 2, 4. The frame shown is `floor(t / frameMs)`. Node state follows spec §5.4: `down` when `up = 0` (the engine reports 1 while any instance is up), `overloaded` when `rejected > 0` or `busy ≥ 0.95`, `busy` when `busy ≥ 0.7`. The engine timeline has no per-edge throughput, so dot density is a **visual approximation**: an edge's rate at frame *k* is its target's `inFlight` divided by the target's in-degree, scaled so the busiest edge in the run gets 12 dots per second of simulated time. Every edge with traffic gets at least 1. With `prefers-reduced-motion`, playback does not start on its own and dots are drawn without trails. |
| R20 | Faults | All 14 kinds are listed. Kinds missing from `capabilities().faults` are disabled with a "coming soon" tooltip. Targets are filtered by role: `instance-down`, `instance-slow` → service; `lb-node-down` → balancer; `db-*` → database; `traffic-surge-3x` → no target; the other kinds need components that do not exist yet. The first target option is "any matching (the engine picks)" (`target: null`). "Random fault" uses `mulberry32(design.seed + 7919 × faults.length)` to pick a supported kind, a matching target and a time between 20% and 70% of the duration, rounded to 100 ms. The same design always draws the same sequence. |
| R21 | Traffic presets | Four built-in presets (our own numbers): quiet (200 rps, 10% writes), lunch peak (3,000 rps, 20%), flash sale (8,000 rps, 30%, surge ×3 at 4 s for 3 s), write storm (2,000 rps, 70%). Users save the current workload as a named preset in IndexedDB. Applying a preset replaces the workload fields and keeps duration, seed and params. |
| R22 | Storage | IndexedDB database `sd-lab`, version 1, stores `designs` (key `id`, index `updatedAt`), `presets` (key `id`) and `kv` (`draft`, `settings`). No count limit. The draft autosaves 1 s after the last change. On open, the Lab restores the draft unless a challenge or template was requested in the URL. |
| R23 | Design file | Export writes `<name>.sdlab.json`: the design with `designFormatVersion: 1`, plus `engineVersion` (informational only). Import validates with a zod schema. Each problem is shown as `<path>: <translated reason>`, with reasons from `importIssue.<zod issue code>`. An unknown component kind is accepted on import and then flagged by validation as `node.unknown-kind`. |
| R24 | Content in the app | Server components read `content/curriculum.json` and `content/challenges/<id>/challenge.json` from the repo (`path.resolve(process.cwd(), "../../content")`). Challenge ids must match `^c-[a-z0-9-]+$` (no path traversal). `start` is normalized with sim-core's serde defaults (label `""`, replicas 1, config `{}`, profile `mixed`, writeRatio 0.2, clients 1000, clientTimeoutMs 1000, duration 10 000, seed **1** per content ruling R2). The chosen mode (`?mode=`, default the first) applies `workloadOverride` (shallow merge; `null` removes a key) and `faults`. `limits` go to `validateGraph`, and the palette greys out kinds outside `allowedKinds`. Node positions come from auto-layout. |
| R25 | Search | The command palette (cmdk, `shouldFilter={false}`) ranks with fuse.js over text folded to lowercase ASCII (NFD with combining marks removed, `đ → d`). Every item indexes both its Vietnamese and English text, so either language finds it. Items: Lab commands, every lesson and challenge in the curriculum (titles plus concept tags), and every component kind with its description. Searching lesson text and engine docs waits for sub-project 4 (no lesson pages yet). |
| R26 | Theme | `data-theme="light|dark"` on `<html>`. The preference (`light`, `dark`, `system`; default `system`) lives in `localStorage["sd-theme"]`. An inline script in `<head>` applies it before first paint. With `system`, a `matchMedia` listener follows OS changes live. Tailwind's `dark:` variant is bound to `[data-theme=dark]`. |
| R27 | Onboarding tour | Our own seven-step tour built on Radix Popover, anchored to `[data-tour="…"]` elements. It starts on the first Lab visit (`localStorage["sd-tour-lab"]` unset) and can be replayed from the help menu. Escape or "Skip" ends it and marks it seen. |
| R28 | CI | New `.github/workflows/web.yml`. Path filters are spec §9 (`apps/web/**`, `packages/**`, `crates/sim-wasm/**`, `crates/sim-core/**`, `content/**`, the workflow file) **plus** the build files (`Dockerfile`, `compose.yaml`, `compose.ci.yaml`, `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`), because a dependency or image change can break the app. The dev image is built with `docker/build-push-action` and a GitHub Actions layer cache; the Playwright browsers live in a cached layer (R4). `compose.ci.yaml` bind-mounts host directories over the pnpm store, the cargo registry and target, and `apps/web/.next`, and `actions/cache` saves them. `engine.yml` switches to the same cached image build, because the image now also installs Chromium. |
| R29 | Test layout | Unit and component tests sit next to their code as `*.test.ts(x)`. They use the `node` environment by default, and component tests opt into jsdom with `// @vitest-environment jsdom`. Engine-backed unit tests use `@sd/sim/node` (same wasm, Node target). E2E tests live in `apps/web/e2e/`. Screenshot baselines live in `apps/web/e2e/__screenshots__/`, are produced only in the container (Linux, Chromium) and are committed through a `.gitignore` exception for `*.png`. Vitest is 5.0.3 in `apps/web`. `packages/sim` keeps its existing 3.2.7. |
| R30 | Performance targets (spec §7) | Measured by `e2e/perf.spec.ts` against `next start` in the container. Lab first load: navigation start → engine status `ready`, under 2 500 ms. Run: the worker round trip for the committed 30-node fixture, under 50 ms (median of 5). Playback: the median `requestAnimationFrame` interval over 180 frames with 30 nodes playing at 1×, at most 17.5 ms (≥ 57 fps). The numbers and the machine go into `docs/perf/lab.md`. A miss is investigated and reported, never relaxed. |
| R31 | Desktop only | Below 1 280 px wide, a dismissible "best on a desktop" banner shows, and the page still renders. Nothing is hidden. |
| R32 | Commit messages | Each task gives its commit message. The plan's messages carry no trailer lines. Trailers follow the executing agent's standing instructions. |

## Global Constraints

- **Every build/test command runs inside the dev container via `./dev <command>`** (for example `./dev pnpm --filter @sd/web test`). Nothing is installed on the host. `docker compose up web` is the one long-running command developers start directly.
- `sim-core` does not change. `sim-wasm` gains only `capabilities()` (R1).
- The app never calls the reference site or any external service at runtime: no remote fonts, no analytics, no telemetry (`NEXT_TELEMETRY_DISABLED=1`), no CDN scripts. `packages/sim/test/no-external-calls.test.ts` keeps scanning `apps/`.
- All user-facing text comes from `apps/web/messages/{vi,en}.json` through `next-intl`. The engine emits codes; the UI translates them. Both catalogs are written separately in natural language; neither is a line-by-line translation of the other. No text, image, icon or styling is copied from the reference product or from books.
- Every interactive control is reachable by keyboard and has an accessible name. Focus is always visible (2 px `--sd-focus` ring, 2 px offset).
- Exact dependency versions only (table above). Do not upgrade during the plan. A broken pin is reported, not silently bumped.
- TypeScript `strict` and `noUncheckedIndexedAccess`. No `any` in `src/` except at the worker message boundary, where values are typed right after receipt.
- Runtime code in `apps/web/src` must not import `@sd/sim/node` (tests only). It imports `@sd/sim` for types and `@sd/sim/web` only inside the worker.
- Before each commit: `./dev pnpm --filter @sd/web lint && ./dev pnpm --filter @sd/web typecheck && ./dev pnpm --filter @sd/web test`.
- A phase ends with the full suite green: `./dev pnpm test` and `./dev pnpm test:web`.
- Commit messages are given in each task (R32).

## Review Focus

1. **The wasm in the browser.** The worker loads the wasm from the hashed `/_next/static/media/*.wasm` URL with `application/wasm`, in `next dev` and `next start`. A failed load or a worker crash shows a retry banner, and retry works (Task 7).
2. **No engine prose, no missing key.** Every engine code has a key in both languages; no English inside Vietnamese text; the lint rule fires (Tasks 4, 8).
3. **Undo/redo and locking.** No operation changes a locked node except moving it; undo restores exactly the previous snapshot; a drag is one step (Task 10).
4. **`SimInput` building.** Groups, positions and UI-only fields never reach the engine; unchanged world parameters are not sent; challenge starts keep their seed of 1 (Tasks 18, 31).
5. **Worker message lifetimes.** Timeline buffers are transferred, not copied. Stale validate replies are dropped. Old `SimRun` handles are freed (Tasks 7, 14, 22).
6. **Playback performance.** The dots layer does not allocate per frame and does not re-render React per frame (Task 27).
7. **Import safety.** A hostile `.sdlab.json` (wrong types, huge arrays, unknown keys, prototype keys) gives a translated issue list and never crashes or pollutes state (Task 30).

## Visual design

The look is our own. The idea is a **lab bench**: warm, quiet surfaces in light mode, ink-blue surfaces in dark mode, one teal signal colour for action and focus, and colour reserved for meaning (edge kinds, node states). Nothing is decorative. Both themes are designed separately: in dark mode, borders and slightly raised surfaces do the work that shadows do in light mode, and every hue is retuned for the dark background instead of inverted.

### Type

- UI font: **Be Vietnam Pro** (400, 500, 600, 700), bundled from `@fontsource/be-vietnam-pro`. It covers Vietnamese diacritics well at small sizes. Numbers, code and JSON use **JetBrains Mono Variable** with `font-variant-numeric: tabular-nums`.
- Scale (size / line height, px): `2xs` 11/16, `xs` 12/16, `sm` 13/20, `base` 14/20 (body default), `md` 16/24, `lg` 18/26, `xl` 22/28, `2xl` 28/34, `3xl` 36/42. Sizes `xl` and above use `-0.01em` letter spacing and weight 600.
- Section labels in panels: `2xs`, weight 600, uppercase, `0.06em` tracking, `text-3`. Metric values: mono `xl` weight 600. Captions: `xs` `text-3`.

### Space, radius, elevation, motion

- Spacing is a 4 px grid (Tailwind's default `--spacing: 0.25rem`). Used steps: 2, 4, 6, 8, 12, 16, 20, 24, 32, 40, 48, 64 px. Control height 32 px (compact rows 28 px, toolbar buttons 32 × 32). Panel padding 12 px; card padding 12–16 px.

```js
// Builds packages/sim/wasm (node + web targets) when it is missing or older than the engine
// sources. Runs before `dev`, `build`, `test` and `typecheck` (plan ruling R3).
import { execFileSync } from "node:child_process";
import fs from "node:fs";
import path from "node:path";
import { fileURLToPath, pathToFileURL } from "node:url";

const repo = path.resolve(path.dirname(fileURLToPath(import.meta.url)), "../../..");
const OUTPUTS = ["packages/sim/wasm/web/sim_wasm_bg.wasm", "packages/sim/wasm/node/sim_wasm_bg.wasm"];
const SOURCES = [
  "crates/sim-core/src",
  "crates/sim-wasm/src",
  "crates/sim-core/Cargo.toml",
  "crates/sim-wasm/Cargo.toml",
  "Cargo.lock",
];

/** Newest modification time (ms) of a file, or of any file under a directory. */
export function newestMtime(p) {
  const st = fs.statSync(p);
  if (!st.isDirectory()) return st.mtimeMs;
  let max = 0;
  for (const entry of fs.readdirSync(p)) max = Math.max(max, newestMtime(path.join(p, entry)));
  return max;
}

/** True when any output is missing or any source changed after the oldest output was built. */
export function isStale(outputs, sources) {
  if (!outputs.every((o) => fs.existsSync(o))) return true;
  const built = Math.min(...outputs.map((o) => fs.statSync(o).mtimeMs));
  return Math.max(...sources.filter((s) => fs.existsSync(s)).map(newestMtime)) > built;
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  const outputs = OUTPUTS.map((p) => path.join(repo, p));
  const sources = SOURCES.map((p) => path.join(repo, p));
  if (isStale(outputs, sources)) {
    execFileSync("pnpm", ["--filter", "@sd/sim", "build:wasm"], { cwd: repo, stdio: "inherit" });
  } else {
    console.log("wasm is up to date");
  }
}
```

```ts
export type Messages = { [key: string]: string | Messages };

/** Nested catalog -> { "a.b.c": "text" }. */
export function flatten(messages: Messages, prefix = ""): Record<string, string> {
  const out: Record<string, string> = {};
  for (const [k, v] of Object.entries(messages)) {
    const key = prefix ? `${prefix}.${k}` : k;
    if (typeof v === "string") out[key] = v;
    else Object.assign(out, flatten(v, key));
  }
  return out;
}

/** Sorted, unique ICU argument names in a message (`{name}`, `{n, plural, …}`). */
export function icuArgs(text: string): string[] {
  const names = new Set<string>();
  for (const m of text.matchAll(/\{\s*([A-Za-z_]\w*)\s*[,}]/g)) names.add(m[1]!);
  return [...names].sort();
}
```

```ts
  const start = css.indexOf(`${selector} {`);
  if (start < 0) throw new Error(`no block ${selector}`);

  const out: Record<string, string> = {};

function luminance(hex: string): number {
  const n = Number.parseInt(hex.slice(1), 16);
  const [r, g, b] = [n >> 16, (n >> 8) & 255, n & 255].map((v) => {
    const c = v / 255;
    return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4;
  }) as [number, number, number];
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}
```

```ts
export type ThemePref = "light" | "dark" | "system";
export type Theme = "light" | "dark";
export const THEME_KEY = "sd-theme";
export const THEME_PREFS: readonly ThemePref[] = ["light", "dark", "system"];

export function resolveTheme(pref: ThemePref, systemDark: boolean): Theme {
  return pref === "system" ? (systemDark ? "dark" : "light") : pref;
}

export function readPref(storage: Pick<Storage, "getItem">): ThemePref {
  const v = storage.getItem(THEME_KEY);
  return v === "light" || v === "dark" || v === "system" ? v : "system";
}

/** Runs in <head> before first paint (plan ruling R26). Keep it dependency-free. */
export const themeScript = `(function(){try{var p=localStorage.getItem("${THEME_KEY}");if(p!=="light"&&p!=="dark")p="system";var d=p==="dark"||(p==="system"&&window.matchMedia("(prefers-color-scheme: dark)").matches);var r=document.documentElement;r.dataset.theme=d?"dark":"light";r.dataset.themePref=p;}catch(e){document.documentElement.dataset.theme="light";}})();`;

export function applyTheme(pref: ThemePref): void {
  const systemDark = window.matchMedia("(prefers-color-scheme: dark)").matches;
  const root = document.documentElement;
  root.dataset.theme = resolveTheme(pref, systemDark);
  root.dataset.themePref = pref;
}
```

```ts
"use client";
import { useCallback, useEffect, useSyncExternalStore } from "react";
import { applyTheme, readPref, THEME_KEY, type ThemePref } from "./theme";

const listeners = new Set<() => void>();
const notify = () => listeners.forEach((l) => l());

function subscribe(l: () => void) {
  listeners.add(l);
  return () => listeners.delete(l);
}
function getPref(): ThemePref {
  try {
    return readPref(localStorage);
  } catch {
    return "system";
  }
}

/** Current preference; follows OS changes live while the preference is "system". */
export function useTheme(): [ThemePref, (p: ThemePref) => void] {
  const pref = useSyncExternalStore(subscribe, getPref, () => "system" as ThemePref);

  useEffect(() => {
    if (pref !== "system") return;
    const mq = window.matchMedia("(prefers-color-scheme: dark)");
    const onChange = () => applyTheme("system");
    mq.addEventListener("change", onChange);
    return () => mq.removeEventListener("change", onChange);
  }, [pref]);

  const set = useCallback((p: ThemePref) => {
    try {
      localStorage.setItem(THEME_KEY, p);
    } catch {
      /* storage unavailable: still apply for this page */
    }
    applyTheme(p);
    notify();
  }, []);

  return [pref, set];
}
```

```ts
  | { type: "engineVersion" }
  | { type: "listComponents" }
  | { type: "defaultCalibration" }
  | { type: "capabilities" }

  runId: number;
  metrics: Metrics;
  events: SimEvent[];
  timeline: { header: TimelineHeader; data: Float32Array };
  traces: TraceSummary[];

  elapsedMs: number;
}

  engineVersion: string;
  listComponents: ComponentMeta[];
  defaultCalibration: Calibration;
  capabilities: Capabilities;
  validate: ValidateResult;
  run: RunResult;
  trace: Trace;
  resultJson: string;
  dropRun: null;
}
```

```ts
import {
  SimInputError,
  SimValidationError,
  type CalibrationOverrides,
  type Node,
  type Sim,
  type SimInput,
  type SimRun,
} from "@sd/sim";
import type { EngineError, EngineRequest, Envelope, Reply, RunResult, ValidateResult } from "./protocol";

/** Runs whose handles the worker keeps for trace(i) and JSON export (R18). */
export const MAX_RUNS = 10;
const COST_CLIENT = "__cost-client";
const COST_EDGE = "__cost-edge";

export interface Handled {
  reply: Reply;
  transfer: Transferable[];
}

function toEngineError(e: unknown): EngineError {
  if (e instanceof SimValidationError) return { kind: "validation", issues: e.issues };
  if (e instanceof SimInputError) return { kind: "input", message: e.message };
  return { kind: "internal", message: e instanceof Error ? e.message : String(e) };
}

export function createHandler(sim: Sim, now: () => number = () => performance.now()) {
  const runs = new Map<number, SimRun>();
  let nextRunId = 1;
  const metas = sim.listComponents();
  const metaByKind = new Map(metas.map((m) => [m.kind, m]));
  const clientKind = metas.find((m) => m.role === "client")?.kind ?? "client";

  /** Plan ruling R10: a 100 ms, zero-traffic run of client -> node prices the node alone. */
  function nodeCost(node: Node, calibration: CalibrationOverrides): number | null {
    const meta = metaByKind.get(node.kind);
    if (!meta) return null;
    const kind = meta.accepts[0];
    if (meta.role === "client" || kind === undefined) return 0;
    const input: SimInput = {
      graph: {
        nodes: [{ id: COST_CLIENT, kind: clientKind, label: "", replicas: 1, config: {} }, node],
        edges: [{ id: COST_EDGE, from: COST_CLIENT, to: node.id, kind }],
      },
      workload: { profile: "mixed", baseRps: 0, writeRatio: 0, clients: 1, clientTimeoutMs: 1000, surge: null, params: {} },
      faults: [],
      durationMs: 100,
      seed: 0,
      calibration,
    };
    try {
      const run = sim.simulate(input);
      try {
        return run.metrics.costPerMonth;
      } finally {
        run.free();
      }
    } catch {
      return null;
    }
  }

  function kept(runId: number): SimRun {
    const run = runs.get(runId);
    if (!run) throw new Error(`unknown run ${runId}`);
    return run;
  }

  function dispatch(r: EngineRequest): [unknown, Transferable[]] {
    switch (r.type) {
      case "engineVersion":
        return [sim.engineVersion(), []];
      case "listComponents":
        return [metas, []];
      case "defaultCalibration":
        return [sim.defaultCalibration(), []];
      case "capabilities":
        return [sim.capabilities(), []];
      case "validate": {
        const issues = sim.validateGraph(r.graph, r.limits ?? undefined);
        const costs: Record<string, number | null> = {};
        for (const n of r.graph.nodes) costs[n.id] = nodeCost(n, r.calibration);
        return [{ issues, costs } satisfies ValidateResult, []];
      }
      case "run": {
        const t0 = now();
        const run = sim.simulate(r.input);
        const tl = run.timeline;
        const result: RunResult = {
          runId: nextRunId++,
          metrics: run.metrics,
          events: run.events,
          timeline: {
            header: { frameMs: tl.frameMs, frames: tl.frames, nodeIds: [...tl.nodeIds], fields: [...tl.fields] },
            // A JS-owned copy (sim-wasm copies it out of wasm memory); transferred, never read again here.
            data: tl.data,
          },
          traces: run.traceSummaries(),
          elapsedMs: 0,
        };
        result.elapsedMs = now() - t0;
        runs.set(result.runId, run);
        while (runs.size > MAX_RUNS) {
          const [oldestId, oldest] = runs.entries().next().value as [number, SimRun];
          oldest.free();
          runs.delete(oldestId);
        }
        return [result, [result.timeline.data.buffer]];
      }
      case "trace":
        return [kept(r.runId).trace(r.index), []];
      case "resultJson":
        return [kept(r.runId).resultJson(), []];
      case "dropRun": {
        runs.get(r.runId)?.free();
        runs.delete(r.runId);
        return [null, []];
      }
    }
  }

  return function handle({ id, request }: Envelope): Handled {
    try {
      const [value, transfer] = dispatch(request);
      return { reply: { id, ok: true, value }, transfer };
    } catch (e) {
      return { reply: { id, ok: false, error: toEngineError(e) }, transfer: [] };
    }
  };
}
```

```ts
import type { EngineError, EngineRequest, Envelope, Reply, ResultOf } from "./protocol";

export interface WorkerLike {
  onmessage: ((e: MessageEvent<Reply>) => void) | null;
  onerror: ((e: ErrorEvent) => void) | null;
  postMessage(message: Envelope, transfer?: Transferable[]): void;
  terminate(): void;
}

/** The worker answered with an error (validation issues, bad input, wasm load failure). */
export class EngineRequestError extends Error {
  constructor(readonly error: EngineError) {
    super(error.kind === "validation" ? "validation" : error.message);
    this.name = "EngineRequestError";
  }
}

/** The worker died or was restarted while the request was pending. */
export class EngineCrashError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "EngineCrashError";
  }
}

type Pending = { resolve: (v: unknown) => void; reject: (e: Error) => void };

export class EngineClient {
  #factory: () => WorkerLike;
  #worker!: WorkerLike;
  #next = 1;
  #pending = new Map<number, Pending>();
  #listeners = new Set<(e: EngineCrashError) => void>();

  constructor(factory: () => WorkerLike) {
    this.#factory = factory;
    this.#spawn();
  }

  #spawn(): void {
    const w = this.#factory();
    w.onmessage = (e) => {
      const r = e.data;
      const p = this.#pending.get(r.id);
      if (!p) return;
      this.#pending.delete(r.id);
      if (r.ok) p.resolve(r.value);
      else p.reject(new EngineRequestError(r.error));
    };
    w.onerror = (e) => {
      e.preventDefault?.();
      this.#fail(new EngineCrashError(e.message || "engine worker error"), true);
    };
    this.#worker = w;
  }

  #fail(err: EngineCrashError, notify: boolean): void {
    for (const p of this.#pending.values()) p.reject(err);
    this.#pending.clear();
    if (notify) for (const l of this.#listeners) l(err);
  }

  request<K extends EngineRequest["type"]>(
    request: Extract<EngineRequest, { type: K }>,
    transfer: Transferable[] = [],
  ): Promise<ResultOf[K]> {
    const id = this.#next++;
    return new Promise<ResultOf[K]>((resolve, reject) => {
      this.#pending.set(id, { resolve: resolve as (v: unknown) => void, reject });
      this.#worker.postMessage({ id, request }, transfer);
    });
  }

  onCrash(listener: (e: EngineCrashError) => void): () => void {
    this.#listeners.add(listener);
    return () => this.#listeners.delete(listener);
  }

  /** Kills the worker (pending requests reject) and starts a fresh one. */
  restart(): void {
    this.#worker.terminate();
    this.#fail(new EngineCrashError("engine restarted"), false);
```

```ts
import type { Calibration, Capabilities, ComponentMeta } from "@sd/sim";
import { createStore } from "zustand/vanilla";
import { EngineRequestError, type EngineClient } from "./client";

export interface EngineInfo {
  version: string;
  components: ComponentMeta[];
  calibration: Calibration;
  capabilities: Capabilities;
}

export interface EngineState {
  status: "idle" | "loading" | "ready" | "error";
  info: EngineInfo | null;
  error: string | null;
  client: EngineClient | null;
  start(): void;
  retry(): void;
}

export function createEngineStore(makeClient: () => EngineClient) {
  return createStore<EngineState>()((set, get) => {
    async function load(client: EngineClient) {
      set({ status: "loading", error: null });
      try {
        const [version, components, calibration, capabilities] = await Promise.all([
          client.request({ type: "engineVersion" }),
          client.request({ type: "listComponents" }),
          client.request({ type: "defaultCalibration" }),
          client.request({ type: "capabilities" }),
        ]);
        set({ status: "ready", info: { version, components, calibration, capabilities } });
      } catch (e) {
        const message = e instanceof EngineRequestError ? e.error.kind : e instanceof Error ? e.message : String(e);
        set({ status: "error", error: message });
      }
    }
    return {
      status: "idle",
      info: null,
      error: null,
      client: null,
      start() {
        if (get().client) return;
        const client = makeClient();
        client.onCrash((e) => set({ status: "error", error: e.message }));
        set({ client });
        void load(client);
      },
      retry() {
        const client = get().client;
        if (!client) return get().start();
        client.restart();
        void load(client);
      },
    };
  });
}

export type EngineStore = ReturnType<typeof createEngineStore>;
```

```yaml
name: web

# Spec §9 path filters, plus the build files (a dependency or image change can break the app).
on:
  pull_request:
    paths: &paths
      - "apps/web/**"
      - "packages/**"
      - "crates/sim-wasm/**"
      - "crates/sim-core/**"
      - "content/**"
      - "Dockerfile"
      - "compose.yaml"
      - "compose.ci.yaml"
      - "package.json"
      - "pnpm-lock.yaml"
      - "pnpm-workspace.yaml"
      - ".github/workflows/web.yml"
  push:
    branches: [main]
    paths: *paths

concurrency:
  group: web-${{ github.ref }}
  cancel-in-progress: true

jobs:
  web:
    name: lint, typecheck, unit, build, e2e + axe (dev container)
    runs-on: ubuntu-latest
    timeout-minutes: 45
    env:
      COMPOSE_FILE: compose.yaml:compose.ci.yaml
      CI_CACHE: ${{ github.workspace }}/.ci-cache
      CI: "true"
    steps:
      - uses: actions/checkout@v4

      # The dev image, with Playwright's Chromium in a cached layer (plan ruling R4).
      - uses: docker/setup-buildx-action@v3
      - name: Build dev image (layer cache)
        uses: docker/build-push-action@v6
        with:
          context: .
          load: true
          tags: system-design-dev:2
          cache-from: type=gha,scope=dev-image
          cache-to: type=gha,mode=max,scope=dev-image

      - name: Restore pnpm store
        uses: actions/cache@v4
        with:
          path: .ci-cache/pnpm-store
          key: pnpm-${{ hashFiles('pnpm-lock.yaml') }}
          restore-keys: pnpm-

      - name: Restore cargo registry and wasm build
        uses: actions/cache@v4
        with:
          path: |
            .ci-cache/cargo-registry
            .ci-cache/cargo-target
          key: cargo-web-${{ hashFiles('Cargo.lock') }}-${{ hashFiles('crates/sim-core/**', 'crates/sim-wasm/**') }}
          restore-keys: cargo-web-${{ hashFiles('Cargo.lock') }}-

      - name: Restore Next build cache
        uses: actions/cache@v4
        with:
          path: .ci-cache/next/cache
          key: next-${{ hashFiles('pnpm-lock.yaml') }}-${{ hashFiles('apps/web/**', 'packages/**') }}
          restore-keys: next-${{ hashFiles('pnpm-lock.yaml') }}-

      - name: Install JS dependencies
        run: ./dev pnpm install --frozen-lockfile

      - name: Build wasm
        run: ./dev pnpm --filter @sd/web ensure-wasm

      - name: Lint
        run: ./dev pnpm --filter @sd/web lint

      - name: Typecheck
        run: ./dev pnpm --filter @sd/web typecheck

      - name: Unit tests
        run: ./dev pnpm --filter @sd/web test

      - name: Next build
        run: ./dev pnpm --filter @sd/web build

      - name: E2E and accessibility (Playwright)
        run: ./dev pnpm --filter @sd/web test:e2e

      - name: Upload Playwright report
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: apps/web/playwright-report
          retention-days: 7
```
